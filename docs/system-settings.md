# 系统设置使用说明

本批新增「系统设置」一级菜单，未改变车队、司机、车辆、独立审核模块的业务职责。原有后台地址继续可用。只管理运营准备配置，不开放真实订单、支付或新的角色登录。

## 二级菜单

| 菜单 | 内容 / 生效范围 |
| --- | --- |
| 网站设置 | 名称、Logo 图片 URL、客服邮箱/电话、默认语言、中英文站点介绍；应用于客户网站页头、页尾和页面标题。已主动选择语言的用户保留自己的选择。 |
| 国家与城市 | 国家/城市列表、搜索、启停筛选、新增/编辑弹窗、中英文名称、排序；管理预约页选项。列入目录不代表已开放当地运输。 |
| 服务区域 | 保留法兰克福候选范围、营业时段和限制说明，不新增地图或电子围栏。 |
| 车型设置 | 六种现有估价车型的中英文名称/说明、排序、载重、尺寸和启停；另展示新增重型车型资料及用户原始备注。车牌等具体车辆档案仍在车辆管理。 |
| 价格与费用 | 保留原有起步费、里程费、附加费、工程税率及价格试算。 |
| 业务参数 | 送达点数量、预约提前量/最远日期、估价有效期、测试里程上限；页面与服务端同时校验。 |
| 审核规则 | 维护各类主体的资料清单；审核动作仍在审核管理。 |
| 内容与公告 | 保留中英文 FAQ、公告与服务说明。 |
| 员工与权限 | 保留创建员工、角色、停用、会话撤销等既有功能，本批不修改任何账号或密码。 |
| 操作日志 | 保留只读业务及员工权限审计。 |

## 修改与发布

1. 国家、城市、车型列表展示当前生效值；未配置的条目展示默认值。网站设置和业务参数同时显示当前生效设置与版本列表。
2. 点击「新增」或「编辑（新草稿）」打开弹窗；输入变更说明，保存草稿。未发布的新增国家/城市不会出现在生效目录中，可在「全部版本 / 草稿」查找。
3. 保存后进入版本详情，管理员核对已保存值，再立即或定时发布。定时时间按 UTC。请先保存编辑内容，再发布。
4. 发布只影响此后读取的配置、估价和新草稿校验。客户页面刷新后加载最新有效配置；服务端始终使用当前生效配置，旧页面可能需要刷新后重试。
5. 已发布版本不可直接编辑；恢复时复制旧版本为新草稿、核对并重新发布。操作及原因均留痕，并保留版本冲突检查。

Logo 采用已有图片的 HTTPS URL 或本站路径，不包含图片上传/媒体库。URL 不能包含用户名/密码；不要填写临时密钥或敏感链接。图片加载失败时显示默认标识。默认语言仅支持英文、中文。

国家代码为不可变的两位大写标识；城市固定标识与所属国家一经保存不可变，中英文显示名称可以改。新增城市前，其所属国家必须已发布（或在默认目录中）。列表无硬删除入口；停用国家也阻止其城市用于新预约。停用国家、城市或车型不会删除历史草稿及原估价快照，重新保存草稿须符合当前有效规则。

## 参数范围与权限

| 参数 | 允许范围 | 初始默认值 |
| --- | --- | --- |
| 最多送达点 | 1–20 | 20 |
| 最早提前预约 | 15–1440 分钟，且小于最远预约窗口 | 15 分钟 |
| 最远预约 | 1–30 天 | 30 天 |
| 估价有效期 | 1–60 分钟 | 10 分钟 |
| 测试里程上限 | 1–500 公里 | 500 公里 |

- 管理员：全部设置、发布、员工与权限及操作日志。
- 运营：国家城市、区域、车型、价格、审核规则和内容的草稿维护；不能发布，不能修改网站设置或业务参数，不能管理员工。网站/参数的公开信息不属于保密信息。
- 审核员：保留审核权限，不展示系统设置，不允许调用设置写接口。

本批不重置密码，不改强制改密标识，不新增认证表迁移。

## 数据迁移与验证

### 中国至中亚测试国家与城市

`data/central-asia-test-locations-20260927.json` 保存用户提供的 5 个国家、28 个城市及英文稳定标识。导入后这些国家和城市会出现在预约页选择器中，但这只代表测试目录可选，不代表路线已核验、已定价或已开放真实接单。

导入脚本要求明确指定本地或生产环境，使用固定记录标识并写入发布审计；重复运行不会新增重复记录，遇到相同国家/城市范围的其他草稿或版本时拒绝覆盖。导入前后会校验车型、价格、服务区域和重型车型资料数量未变化。

```bash
node scripts/import-central-asia-locations.mjs --check-local
node scripts/import-central-asia-locations.mjs --apply-local
node scripts/import-central-asia-locations.mjs --check-production
node scripts/import-central-asia-locations.mjs --apply-production
```

用户原始清单把「明斯克」列在俄罗斯下。系统依照原始清单暂存为 `RU:Minsk`，内部标题与审计均标记“待确认”；明斯克通常属于白俄罗斯，正式业务使用前应确认是否改为白俄罗斯（BY）。

### 用户提供的 10 种重型车型

`data/vehicle-types-20260927.json` 保存用户提供的原始名称与备注。`0005_vehicle_type_catalog.sql` 为资料车型建立独立目录，原六档估价车型及价格规则不变。

重型目录包含大通道 5/6 轴、120 立方车 5/6 轴、130/140 立方车、13 米平板 5/6 轴、17 米平板车 5/6 轴。四种平板车的备注为空，吨位表述仅为用户提供的业务备注，不推导为统一、已核验的载重上限。未提供的英文名称、规格和价格不补造。

车型设置中的「重型车型资料」只供后台查看、搜索，不直接开放客户预约、自动估价，也不扩展当前司机/车辆建档的车型选项。后续完成规格、承运规则与定价后再单独接入。

导入脚本默认要求明确选择操作环境。查询不写入；导入保留已有记录，不覆盖冲突内容，复跑相同内容不重复插入，同时写入业务审计。线上只访问固定业务库，不访问认证库。

```bash
node scripts/import-vehicle-types.mjs --check-local
node scripts/import-vehicle-types.mjs --apply-local
node scripts/import-vehicle-types.mjs --check-production
# 仅在明确获得线上写入授权后执行（令牌通过环境提供）
node scripts/import-vehicle-types.mjs --apply-production
```

### 系统设置迁移

`migrations/0004_system_settings.sql` 只增加 `ops_settings` 表、索引和 `ops_all_configs` 视图。原 `ops_configs` 表及已有业务数据保留，避免重建已有约束。认证库不受影响。无须导入真实示例资料。

本地：先运行 `pnpm db:migrate:local`，再运行客户站点与本地后台。未来发布时必须先应用业务库迁移，再发布客户 Worker 和后台 Worker；现有部署脚本及 GitHub 工作流按此顺序处理迁移。此文档不代表已经发布线上。

验证命令：

```bash
pnpm check
node scripts/operations-browser-smoke.mjs ../qa/system-settings
node scripts/browser-smoke.mjs http://127.0.0.1:5173 ../qa/system-settings-public
node scripts/settings-frontend-smoke.mjs http://127.0.0.1:5173 ../qa/system-settings-public
```

后台测试使用独立内存数据库及合成账号；前台设置测试通过本地浏览器网络桩验证配置渲染，不写数据库。原预约浏览器测试只在本地/预览创建并清理自己的测试草稿。测试不会读取生产凭据或更改线上账号。
