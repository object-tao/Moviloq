# Moviloq 平台后台、司机端与车队端规划

日期：2026-09-13。状态：补充需求与实施顺序草案；只有管理域名与首位管理员邮箱已由用户确认，未把规划功能标记为已经实现。

## 1. 当前实际状态

客户网站已具备中英文运输规划、估价和浏览器草稿。现有数据库有用户、司机、车队、车辆、订单和审核相关的初始表，但建表不等于业务已经实现：没有管理员登录、司机入驻审批、车队调度或真实接单功能。

本轮建立独立 Worker `moviloq-admin`，用于 `admin.moviloq.com`。当前是明确标示未启用的受限入口，业务访问返回 403；只有静态说明、样式、robots 和不含业务资料的健康检查。没有数据库或客户 Worker 的服务绑定，不能查看或修改客户草稿。没有默认密码，也不会凭客户端传来的邮箱、角色或 Cookie 授权。

正式管理后台必须在身份认证、MFA、服务端角色权限和审计完成后另行开通。首位管理员已确认，其邮箱只用于受控授权配置，不写入公开页面或仓库。

## 2. 四个产品入口

| 产品端 | 域名 | 使用对象 | 本轮状态 |
| --- | --- | --- | --- |
| 客户端 | `moviloq.com` | 个人、企业发货人 | 规划与草稿已上线 |
| 平台后台 | `admin.moviloq.com` | 平台内部运营人员 | 独立受限入口；登录和管理功能未开通 |
| 司机端 | 建议 `driver.moviloq.com` | 独立司机、车队司机 | 规划中，未绑定域名或发布 |
| 车队端 | 建议 `fleet.moviloq.com` | 合作车队老板、调度、财务 | 规划中，未绑定域名或发布 |

管理员使用独立身份边界。司机和车队共享承运方身份体系、业务数据和受控 API，但会话按产品端隔离；不在 `.moviloq.com` 上放所有端共用的管理员 Cookie。平台后台不等于车队后台。

## 3. 参考与本地化边界

本轮核对的 Lalamove 公开产品资料支持“独立司机端 + 车队管理门户”的产品拆分：车队门户管理司机、车辆及配对，司机端查看可用订单、自主选择运输任务并查看收入。这是功能参考，不是对德国站全部功能的断言，也不照搬其他市场的准入条件、币种、收费或结算规则。[车队管理参考](https://www.lalamove.com/en-ph/fleet-management)、[司机端参考](https://www.lalamove.com/en-sg/driver)。

Moviloq 首发仍是法兰克福、自助撮合、中文和英文。界面与通知预留德语；德国/欧盟实际资质清单、用工关系、运输合同、支付和隐私要求另行审核，不由“抢单”或“派单”的 UI 自动决定法律责任。

## 4. 平台后台模块

| 模块 | 第一阶段能力 | 边界 |
| --- | --- | --- |
| 工作台 | 待审核、证件到期、订单异常等真实待办 | 没有数据时显示空状态，不用虚构业务指标 |
| 司机/承运方审核 | 查看申请、补件、通过/拒绝、暂停/恢复及原因 | 必填资质由地区和车型规则决定 |
| 车队管理 | 公司资料、管理员、关联司机/车辆、合作状态 | 不能把车队账号升为平台管理员 |
| 车辆与证件 | 车型能力、审核、有效期、历史版本 | 证件私有存储，短时授权访问 |
| 订单运营 | 筛选订单、时间线、投诉和异常协助 | 草稿不是订单；默认不浏览匿名草稿中的联系人等私人内容 |
| 服务区与计价 | 城市/车型/附加费规则的草稿、审核、发布和版本 | 新规则不重算历史成交价；高风险发布二次确认 |
| 用户与权限 | 邀请、角色、停用、会话撤销 | 禁止公开注册管理员 |
| 审计 | 操作者、对象、时间、原因、前后差异 | 普通后台人员不可修改或删除审计记录 |
| 财务与争议 | 待后续支付接入后查看交易、退款和对账 | 不先做没有实际资金依据的钱包余额 |

管理角色：平台所有者/超级管理员、运营、审核员、客服、财务、只读审计员。首次开通仅指定管理员；后续成员须经邀请，按需授权。资金、高权限授予和关键计价发布的双人复核作为正式交易开放门槛之一；仅有一名管理员时不开放需双人复核的动作。

## 5. 司机端：移动优先

首阶段用响应式 Web/PWA 完成入驻和前台履约验证。原生 App 的必要性由后台持续定位、推送和弱网实测决定，不宣称 PWA 能稳定进行后台实时定位。

功能清单：

- 身份登录、资料填写、语言和通知设置；区分独立承运人、车队所属司机。
- 驾驶资格、车辆、保险等所需资料提交、补件、审核状态与到期提醒。
- 选择当前已审核车辆，上线/下线；未审核、被冻结或证件过期时不能接新单。
- 订单大厅：车型、货物、区域、路线、时窗、预计报酬及计价方式；接单前隐藏不必要的姓名、电话、精确门牌。
- 独立承运方自主接单；车队司机只执行其有权限承接或获派的任务。
- 按顺序确认出发、到达提货、完成装货、各站送达；导航跳转、异常上报、联系客户。
- 每站签收：收货信息、照片/签名、失败原因、时间记录；证据与订单、站点绑定。
- 收入明细区分预计、已完成、待结算、已结算；实际金额来源于经确认的订单与支付记录。
- 弱网状态提示与请求重试，避免重复接单、重复提交签收；重要操作由服务器决定结果。

独立承运人与车队雇员可能承担不同合同角色。必须分别记录经营主体、实际司机和实际车辆，不能把所有司机一律视为与客户签约的经营者。

## 6. 车队端：运营管理门户

车队本身不“抢司机账号的单”，司机也不共享老板账号。车队老板可邀请调度、财务和司机；每个成员使用自己的身份。

| 角色 | 允许的主要动作 | 不允许的动作 |
| --- | --- | --- |
| 老板/车队管理员 | 管理本车队成员、车辆、资料、经营设置 | 审批自身资质、访问其他车队、授予平台权限 |
| 调度员 | 看本车队可用司机/车辆、安排符合条件的任务、处理执行异常 | 改收款账户、改平台费率、强行覆盖司机冲突 |
| 财务 | 看本车队账单、佣金/费用、结算和导出 | 修改司机证件、派单、查看无业务需要的定位轨迹 |
| 商务（后续） | 询报价、合作线路资料 | 擅改已确认合同或已接受订单 |
| 司机 | 看本人获派/允许承接的任务及本人相关收入 | 浏览整个车队客户名单、其他司机证件或全队账务 |

第一阶段：车队入驻、公司资料、邀请司机、车辆登记、司机与车辆配对、审核状态、到期提醒、成员权限。司机加入/退出需要确认并保留记录；有执行中任务时不能直接删除或转移司机/车辆。

第二阶段：车队订单看板、已承接任务的内部调度、司机确认、冲突校验、履约进度、异常和签收。司机可用性、驾驶资格、车辆容量、任务时窗需同时满足；司机拒绝或超时后回到车队调度队列，不能静默转给无关司机。

第三阶段：结算报表、客户/线路模板、报价审批、固定班次与团队协作。合同价、企业账期和跨境整车/零担属于后续商业流程，未默认放入首发接单范围。

## 7. 两种订单链路分开设计

自助撮合：客户确认需求与报价 → 订单发布给合格承运方 → 承运方自愿接受 → 服务端原子锁定 → 实际司机/车辆确认 → 提货 → 逐站送达 → 签收 → 结算。

车队协作：客户订单获得车队作为承运方的确认 → 车队调度选择合格司机及车辆 → 司机确认 → 履约 → 签收 → 按已确认的结算关系对账。平台只做有权限、有记录的运营协助，不能用“后台改司机”绕过确认过程。

后续托管项目/线路包干需单独定义商务报价、签约主体、承诺、调度权限和责任链，再启用。车队管理功能本身不意味着当前自助撮合业务自动变成平台自营或托管运输。

## 8. 数据模型补充计划（本轮不迁移）

在现有 users / organisations / fleets / driver_profiles / vehicles / partner_documents / assignments 等基础上补充：

- 平台角色与细粒度权限；业务组织类型与组织成员关系。
- 车队成员邀请、司机归属有效期和状态、司机与车辆配对历史。
- 明确经营承运主体与实际司机/车辆的区别；订单保存成交及承接快照。
- 接单竞争的唯一活动承接约束、车队预留/确认超时；不能只用页面按钮禁用处理并发。
- 订单/各站状态机和追加事件、异常与签收证据。
- 资料审核申请、补件、版本和私有文件访问审计。
- 计价版本、审批和生效时刻；后续账务采用最小货币单位及可对账流水。

所有车队查询与写入必须按服务器验证的成员身份绑定 `fleet_id` / `organisation_id`，不可相信客户端传入的租户 ID。每个主要操作都需要越权、撤销权限、过期证件、并发与幂等测试。

## 9. 安全及开放顺序

1. 管理员域名入口、默认拒绝访问、独立部署（本轮范围）。
2. 受邀管理员身份验证、Cloudflare Access、MFA、JWT 签名/签发者/受众/有效期验证、服务端 RBAC、审计与会话退出。
3. 平台审核中心 + 车队入驻/成员/车辆管理 + 司机入驻，实现完整审核闭环。
4. 补齐客户身份与地图/服务区后，联调订单发布、接单/车队调度、履约和签收。
5. 公司、合同、隐私、保险与支付条件确认后，开放真实交易；德语和欧洲跨境整车/零担分期推进。

仅添加 Access 登录页面或检查请求中的邮箱字段不足以完成后台安全。源 Worker 必须验证签名令牌并执行权限检查；独立 MFA 可用于在邮箱验证码/身份提供商登录之后增加验证。[JWT 验证参考](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)、[独立 MFA 参考](https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/independent-mfa/)。

## 10. 本轮待配合项

当前 API Token 读取 Zero Trust 组织设置返回 HTTP 403 / code 10000，尚不能完成组织配置。需在指定 Moviloq 账户范围补充 Access 组织/身份提供商/组配置权限，并确认 Access 应用与策略编辑权限。不要把账户密码、验证码、恢复码或 API Token 写入此文档或公开仓库。

如果首次开通 Cloudflare Zero Trust 需要套餐/条款确认，由账号所有者完成；不自动接受付费升级。身份认证与 MFA 的个人验证步骤也必须由管理员本人完成。

待业务确认：司机端/车队端建议域名、首批车队信息、独立承运方与车队订单的结算对象、车队司机是否可在车队授权下自主接单。暂定一期只绑定一个有效车队归属，加入需本人确认；不擅自导入或邀请搭档及车队成员。
